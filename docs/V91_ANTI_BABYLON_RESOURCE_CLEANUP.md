# V91 Anti-Babylon Resource Cleanup — Integration Contract
Status: DOCUMENTED_PROPOSAL. No production activation is implied.

The resource-cleanup policy is an advisory decision contract, not an enforcement authority. Before a measure is adopted, record a sourced baseline, full lifecycle cost, intended outcome, legal basis, affected parties, ecological and service-quality impacts, verification method, deadline, and rollback condition.

Priority order: prevent waste; maintain and repair; reuse and refurbish; recycle; dispose only when higher-value options are not feasible. Apply this across materials, energy, water, food, logistics, procurement, public finance, and administration.

Required invariants:
- CLAIM != EVIDENCE.
- REQUEST != AUTHORIZATION; DETECTION != AUTHORIZATION.
- ISOLATE_NOT_DESTROY.
- PRIVILEGES_NEW <= PRIVILEGES_OLD.
- Recovery > Optimization.
- Unknown or missing measurements => UNKNOWN / REVIEW_REQUIRED.
- No automatic spending, deletion, penalties, service shutdown, or external action from a score or heuristic alone.
- Protect human dignity, fundamental rights, essential services, accessibility, and due process.
- Prefer removing duplicate work and reusing existing infrastructure before adding systems.
- A new build is justified only by documented need and a transparent lifecycle comparison.

Verification requires exact revision, test command, environment, timestamp, raw result, and known limitations. A passing test does not establish production readiness or real-world savings. This file documents policy; integration into runtime behavior must be separately implemented, reviewed, tested, and authorized.
